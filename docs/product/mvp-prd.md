# 上下文阅读助手 MVP PRD

> 文档状态：需求基线 v1.0  
> 产品形态：Chrome / Edge 桌面浏览器插件  
> 目标用户：个人用户  
> 覆盖内容：MVP PRD、页面交互流程、验收标准

## 1. 产品概述

### 1.1 问题背景

用户阅读外部技术博客时，经常会遇到不理解的专业术语、代码片段、架构图或流程图。当前通常需要复制文字或截图，切换到其他大模型产品，再粘贴内容并重新描述问题。

这一过程存在三个核心问题：

1. 操作链路长，打断连续阅读。
2. 外部模型缺少文章全文和当前阅读位置，容易脱离原文语境。
3. 图片需要额外截图和上传，架构图与前后文之间的关系容易丢失。

### 1.2 产品定义

上下文阅读助手是一款与当前网页绑定的浏览器插件。用户在某个技术博客页面手动启用后，插件自动解析该页面的正文结构、代码块和图片。用户可以针对选中文字、网页图片、框选区域或文章全文直接提问，系统结合当前文章上下文和模型的通用知识回答

### 1.3 核心价值

让用户在不离开当前阅读页面的情况下完成“发现疑问、提问、理解、回到原文继续阅读”的闭环。

### 1.4 MVP 成功定义

本产品仅供个人使用，MVP 暂不设置业务增长指标。满足以下结果即可视为产品能力成立：

- 用户无需复制文章全文或切换应用即可提问。
- 文本、图片和全文问题都能结合当前文章语境回答。
- 页面切换后，各页面上下文彼此隔离且可以恢复。

## 2. 用户与场景

### 2.1 目标用户

需要频繁阅读外部技术博客、开发文档和工程实践文章的个人用户。

### 2.2 核心场景

#### 场景 A：术语解释

用户选中不理解的专业名词，直接询问“它在本文中具体是什么意思”，回答同时说明通用定义和本文语境。

#### 场景 B：段落解释

用户选中一段复杂表述，要求简化解释、举例或说明它与前文结论的关系。

#### 场景 C：图片理解

用户点击文章中的架构图，或框选图片与相邻说明文字，要求解释组件、数据流、步骤或设计目的。

#### 场景 D：全文提问

用户未选中具体内容，直接询问文章的核心观点、方案取舍或某个概念在全文中的作用。

#### 场景 E：多页面切换

用户暂时切换到其他页面查看资料。新页面拥有独立上下文；返回原页面时，原有解析结果和对话恢复。

## 3. 产品原则

1. **原文优先**：回答首先服从当前文章内容，不能用通用知识覆盖或曲解原文。
2. **语境一致**：回答应优先依据当前文章；文章信息不足时，再使用模型通用知识补充。
3. **上下文可见**：用户能看到当前页面是否已经完成解析，以及本次问题关联了什么内容。
4. **少打扰**：插件默认不处理页面，必须由用户在每个新页面上手动启用。
5. **会话隔离**：不同页面的正文、图片和问答不能相互污染。
6. **用户可控**：用户决定是否保留对话记录，并可主动清除临时上下文。
7. **如实失败**：页面或图片无法完整读取时必须明确提示，不能假装已经理解。

## 4. MVP 范围

### 4.1 P0 能力

- Chrome / Edge 桌面端浏览器插件。
- 每个新页面由用户手动启用。
- 自动提取常规技术博客的标题、URL、正文、标题层级、段落、列表、代码块和图片信息。
- 展示页面解析状态。
- 支持选中文字提问。
- 支持点击网页图片提问。
- 支持框选可见页面区域并基于截图提问。
- 支持不选中内容、直接针对全文提问。
- 回答结合文章上下文和模型自身的通用知识。
- 支持当前页面内连续追问。
- 支持多个页面上下文的自动创建、隔离、切换和恢复。
- 正文、图片和临时上下文在当前标签页会话内保存。
- 用户可选择是否在本地保留对话记录。
- 用户配置单一模型所需的 API Key。
- 模型和 API 的具体实现预留配置位置，开发前再确定。

### 4.2 非目标

MVP 不包含：

- 多模型选择、模型路由、自动降级或效果比较。
- 产品账号、云端同步、计费和自建业务服务端。
- 联网搜索；“外部知识”仅指所接入模型自身具备的通用知识。
- PDF、视频、音频和移动端网页的专项支持。
- 多页面内容合并为一个知识库。
- 跨文章联合问答。
- 长期个人知识库、笔记管理、分享和团队协作。
- 自动启用网站列表。
- 登录受限网站和特殊站点的专项适配。
- 无限滚动、Canvas、iframe 或强交互页面的完整解析保证。
- 运营后台和业务指标体系。

## 5. 产品界面

### 5.1 插件入口

浏览器工具栏中的插件图标，承担以下功能：

- 展示当前页面状态。
- 手动启用当前页面。
- 打开或收起侧边栏。

### 5.2 对话侧边栏

侧边栏是主要交互区域，至少包含：

- 当前页面标题与解析状态。
- 当前问题关联内容的简要提示。
- 对话消息列表。
- 问题输入框与发送按钮。
- 图片选择和区域框选入口。
- 停止生成、重试和清除当前上下文操作。

### 5.3 文字快捷入口

用户选中文字后显示轻量操作入口。点击后打开侧边栏，并将选中文字作为本次问题的焦点内容。

快捷入口不应遮挡选中文字或影响网页原有复制操作。

### 5.4 图片与区域选择

- **点击图片**：用户进入图片提问模式后，点击文章中的图片，将原图或可获取的最高可用清晰度图片加入问题上下文。
- **框选区域**：用户拖动选择当前可见网页区域，插件生成截图，并保留框选区域附近可提取的文本信息。

### 5.5 设置页

MVP 设置项包括：

- API Key。
- 是否保留对话记录。
- 清除全部本地对话记录。

模型标识和 API 地址属于实现侧预留配置，不作为用户设置项。MVP 不展示模型选择器。

## 6. 功能需求

### FR-01 手动启用

- 插件不得在未启用的页面上自动提取或发送正文和图片。
- 用户对一个新页面执行启用后，插件开始自动解析该页面。
- 同一页面已启用后，切走再返回不要求重复启用。
- 新页面自动创建独立的上下文容器，但在用户启用前保持“未启用”状态。

### FR-02 页面解析

插件应尽可能提取：

- 页面标题与规范化 URL。
- 文章标题、作者、发布时间（页面可识别时）。
- 标题层级与章节关系。
- 正文段落、列表和引用。
- 代码块及其语言标记（可识别时）。
- 图片地址、图片本身、替代文本和图片说明。
- 图片所属章节及前后相邻文本。

系统应展示以下状态：

- 未启用。
- 正在解析。
- 上下文已就绪。
- 部分内容无法读取。
- 解析失败。

“上下文已就绪”表示系统已经具备在用户提问时检索和使用当前文章内容的能力，不代表每次都将全文原样发送给模型。

### FR-03 文本提问

- 用户可以选中术语、句子或段落发起提问。
- 系统应将选中文字、所属章节、前后文及全文相关内容组合为问题上下文。
- 用户可以编辑或取消系统自动关联的选中文字。

### FR-04 图片提问

- 用户可以点击文章中的图片发起提问。
- 系统应同时关联图片、图片说明、所属章节、前后文和全文相关内容。
- 图片无法获取原始资源时，可以使用页面截图，但必须提示实际使用的是截图。
- 图片加载失败、跨域限制或清晰度不足时，应明确提示。

### FR-05 区域框选提问

- 用户可以框选当前页面可见区域。
- 框选完成后应提供预览，用户确认后才加入问题上下文。
- 用户取消时不得保留该截图。
- 截图应结合可获取的附近文本和页面章节信息，而不是单独发送图片。

### FR-06 全文提问

- 用户无需选中内容即可对当前文章提问。
- 系统应从全文中选择与问题相关的章节和片段。
- 如果当前页面尚未启用或解析未完成，应阻止发送并说明原因。

### FR-07 回答规范

回答应包含或明确表达：

- 对用户问题的直接回答。
- 该概念或内容在本文中的具体含义。
- 必要时补充的模型通用知识。

回答不展示原文出处、段落编号、引用卡片或点击定位入口。文章未提供足够信息或模型无法确定时，应直接说明信息不足，不能把通用知识表述为文章结论。

### FR-08 连续追问

- 同一页面内的后续问题可以引用此前问答。
- 用户明确指代“上面这张图”“刚才的概念”时，系统应保留必要的对话上下文。
- 对话过长需要裁剪时，应优先保留当前问题、最近对话、已选内容和相关原文，不得静默混入其他页面内容。

### FR-09 多页面上下文

上下文按“标签页 + 页面”隔离管理：

- 切换到另一个标签页时，当前上下文进入暂停状态，不被删除。
- 同一标签页跳转到新 URL 时，为新页面创建独立上下文。
- 通过前进、后退或再次访问返回原页面时，恢复该标签页内已有的页面上下文。
- 返回已启用页面时，恢复解析结果和对话，不重复要求手动启用。
- 返回未启用页面时，仍保持未启用。
- 关闭标签页时，清除该标签页下的正文、图片和临时页面上下文。
- 关闭浏览器会话时，清除所有未明确保留的临时页面上下文。

MVP 的建议上下文标识为 `tabId + 规范化 URL`。URL 规范化规则和刷新后的内容更新策略需在技术设计中确认。

### FR-10 对话记录

- 默认是否保留对话记录需在实现前确定，用户始终可以在设置中修改。
- 关闭“保留对话记录”时，关闭标签页即清除该标签页中的对话。
- 开启后，仅在浏览器本地保存问答文本。
- 已保留的对话记录与临时正文、图片数据分开存储。
- 保留对话记录不代表长期保存文章全文或图片。
- 用户可以删除单个页面的对话或清除全部对话。

### FR-11 模型 API

- MVP 仅接入一个同时支持文本与图片输入的模型。
- 用户自行提供 API Key。
- 实现侧预留 API 地址、模型标识、文本输入、图片输入、流式输出、错误和重试能力。
- API 地址和模型标识由产品实现固定，不允许用户在 P0 中选择或切换。
- 具体模型、API 协议、请求限制和流式输出能力在开发前确定。
- 请求失败时允许用户重试，但不得自动切换到其他模型。

### FR-12 隐私与安全

- 页面未手动启用前，不处理或发送页面正文和图片。
- 页面启用后，插件可以自动解析内容，并按最终模型方案执行必要的远程处理。
- UI 应明确告知当前页面内容可能发送至用户配置的模型 API。
- API Key 仅保存在浏览器本地，不进入网页 DOM、页面脚本、对话记录或普通日志。
- 正文、图片和截图不得进入长期存储，除非未来另有明确需求并由用户主动确认。
- 清除操作完成后，相关本地数据应不可再从产品界面恢复。

### FR-13 错误处理

至少覆盖：

- 页面无可识别正文。
- 页面仅解析出部分内容。
- 图片无法获取或图片清晰度不足。
- 区域截图失败。
- API Key 缺失或无效。
- API 限流、超时、网络错误和服务不可用。
- 模型不支持图片输入。

错误提示必须说明失败对象和可执行的下一步，例如重新解析、重新框选、检查 API Key 或重试请求。

## 7. 页面交互流程

### 7.1 首次配置

```text
安装插件
  -> 打开设置页
  -> 输入 API Key
  -> 插件验证 API Key 必要字段
  -> 配置完成
```

如果模型 API 尚未最终确定，开发态可使用实现侧占位配置，但正式可用版本必须提供明确配置说明。

### 7.2 启用当前页面

```text
用户打开技术博客
  -> 点击插件图标
  -> 当前页面显示“未启用”
  -> 用户点击“启用当前页面”
  -> 展示数据处理提示
  -> 自动解析正文、结构和图片
  -> 显示“上下文已就绪”或“部分内容无法读取”
  -> 打开侧边栏开始提问
```

### 7.3 选中文字提问

```text
用户选中文字
  -> 出现轻量提问入口
  -> 用户点击入口
  -> 侧边栏展示已关联的文字和章节
  -> 用户输入问题
  -> 系统检索全文相关内容
  -> 模型回答
```

### 7.4 图片提问

```text
用户选择“图片提问”
  -> 页面进入图片选择模式
  -> 用户点击目标图片
  -> 侧边栏预览图片及关联章节
  -> 用户输入问题并发送
  -> 系统组合图片、图注、前后文和全文相关内容
  -> 模型回答并区分原文依据与补充知识
```

### 7.5 区域框选提问

```text
用户选择“框选区域”
  -> 页面进入遮罩选择状态
  -> 用户拖动框选
  -> 展示截图预览
  -> 用户确认或取消
  -> 确认后输入问题
  -> 系统组合截图、附近文字和文章上下文
  -> 模型回答
```

### 7.6 页面切换与恢复

```text
页面 A 已启用并存在对话
  -> 用户切换至页面 B
  -> 页面 A 上下文暂停
  -> 页面 B 创建独立、未启用的上下文
  -> 用户可手动启用页面 B
  -> 用户返回页面 A
  -> 自动恢复页面 A 的解析结果和对话
```

### 7.7 关闭与清理

```text
用户关闭标签页
  -> 清除该标签页下的正文、图片和临时上下文
  -> 若未开启对话保留，同时清除对话
  -> 若已开启对话保留，仅保留问答文本
```

## 8. 状态模型

单个页面上下文至少具有以下状态：

```text
UNACTIVATED
  -> PARSING
  -> READY
  -> PARTIAL
  -> FAILED

READY / PARTIAL
  -> ASKING
  -> ANSWERING
  -> READY / PARTIAL

任意活动状态
  -> SUSPENDED
  -> 恢复到离开前状态

标签页关闭
  -> DISPOSED
```

约束：

- `UNACTIVATED` 状态不得提取或发送文章内容。
- `FAILED` 状态允许重新解析。
- `PARTIAL` 状态允许提问，但每次回答都应携带上下文不完整提示。
- `SUSPENDED` 只表示页面暂时不可见，不代表数据被清除。
- `DISPOSED` 后临时上下文不可恢复。

## 9. 验收标准

### AC-01 新页面必须手动启用

**Given** 用户首次打开一个普通技术博客页面  
**When** 用户尚未点击“启用当前页面”  
**Then** 插件显示“未启用”，不提取、不发送页面正文或图片，也不允许发送基于页面的提问。

### AC-02 启用后自动解析

**Given** 当前页面尚未启用且包含可识别正文和图片  
**When** 用户点击“启用当前页面”  
**Then** 插件自动解析正文结构、代码块和图片信息，并最终显示“上下文已就绪”或“部分内容无法读取”。

### AC-03 选中文字提问包含局部与全文上下文

**Given** 当前页面已就绪  
**When** 用户选中一个术语并发起提问  
**Then** 请求上下文至少包含选中文字、所属章节、邻近段落和全文相关片段，回答说明该术语在本文中的含义。

### AC-04 普通段落可以解释

**Given** 用户选中一个复杂段落  
**When** 用户要求“用更简单的话解释”  
**Then** 回答围绕所选段落展开，不回答无关章节。

### AC-05 网页图片可以提问

**Given** 页面中存在可读取的架构图  
**When** 用户进入图片提问模式、选择图片并发送问题  
**Then** 模型请求包含图片及其图注、所属章节和邻近文本，回答结合图片与文章语境。

### AC-06 图片降级为截图时明确提示

**Given** 插件无法获取图片原始资源但可以截取页面显示内容  
**When** 用户选择该图片提问  
**Then** 插件使用截图并明确显示“本次使用页面截图”，不将截图描述为原始图片。

### AC-07 区域框选需用户确认

**Given** 用户进入区域框选模式  
**When** 用户完成框选  
**Then** 插件先展示截图预览，只有用户确认后才将截图加入问题；取消后不保留截图。

### AC-08 支持全文提问

**Given** 页面上下文已就绪且用户未选择任何内容  
**When** 用户询问文章整体观点  
**Then** 系统从全文选择相关章节回答；文章没有提供足够信息时必须说明。

### AC-09 回答不展示原文出处

**Given** 模型基于文章内容完成回答  
**When** 回答展示完成  
**Then** 页面不展示原文出处、段落编号、引用卡片或点击定位入口。

### AC-10 连续追问保持当前页面语境

**Given** 用户刚针对一张图片获得回答  
**When** 用户追问“这里为什么不用另一种方案”  
**Then** 系统能够关联上一轮图片和回答，不要求用户重新选择图片。

### AC-11 页面上下文相互隔离

**Given** 页面 A 和页面 B 均已启用  
**When** 用户在页面 B 提问  
**Then** 请求不得包含页面 A 的正文、图片或对话，除非未来新增且由用户主动触发跨页面能力。

### AC-12 返回原页面时恢复

**Given** 页面 A 已启用并存在对话，用户随后切换到页面 B  
**When** 用户返回页面 A  
**Then** 插件恢复页面 A 的解析状态、已选内容和对话，不要求重新启用或重新开始会话。

### AC-13 新页面仍需手动启用

**Given** 用户已在页面 A 启用插件  
**When** 用户跳转到从未启用的页面 B  
**Then** 页面 B 创建独立上下文但保持“未启用”，不得沿用页面 A 的启用状态自动解析正文。

### AC-14 关闭标签页清除临时内容

**Given** 一个标签页中存在多个页面的解析结果和图片  
**When** 用户关闭该标签页  
**Then** 该标签页下的正文、图片、截图和临时页面上下文全部清除。

### AC-15 对话保留开关生效

**Given** 用户关闭“保留对话记录”  
**When** 用户关闭对应标签页  
**Then** 对话与临时上下文一并清除。

**Given** 用户开启“保留对话记录”  
**When** 用户关闭对应标签页  
**Then** 本地仅保留问答文本，不保留文章全文、图片或截图。

### AC-16 单模型配置

**Given** 用户打开设置页  
**When** 查看模型相关设置  
**Then** 页面只展示单一模型所需的 API Key，不出现 API 地址、模型标识、模型列表、模型切换或自动降级选项。

### AC-17 API Key 缺失时阻止请求

**Given** 用户未配置 API Key  
**When** 用户尝试发送问题  
**Then** 插件阻止请求，提示配置 API Key，并提供进入设置页的入口。

### AC-18 API 失败时可重试但不切换模型

**Given** 模型 API 返回超时、限流或服务不可用  
**When** 本次回答失败  
**Then** 插件保留用户问题并提供重试，不自动调用其他模型。

### AC-19 部分解析不得伪装完整

**Given** 插件只读取到部分文章或无法读取某张图片  
**When** 用户基于当前页面提问  
**Then** UI 和回答均提示上下文不完整，并避免声称已经理解全文或图片。

### AC-20 清除操作不可从产品界面恢复

**Given** 用户主动清除当前页面上下文或全部本地对话  
**When** 清除完成  
**Then** 对应内容不再出现在侧边栏、历史记录或页面恢复流程中。

## 10. MVP 发布门槛

只有同时满足以下条件才可视为 MVP 完成：

- AC-01 至 AC-20 全部通过。
- 至少在 10 篇结构不同的公开技术博客上完成手工验证。
- 至少覆盖纯文本文章、包含代码块的文章、包含架构图的文章三类页面。
- 未发现不同页面上下文串用问题。
- 未发现 API Key 出现在网页 DOM、普通日志或导出的对话记录中。
- 页面关闭后的临时正文、图片和截图均按要求清除。

## 11. 已确认决策

- 产品供个人使用。
- 主要阅读对象是外部技术博客网页。
- 图片理解属于 P0。
- 允许使用模型自身的外部通用知识。
- 每个新页面必须手动启用。
- 启用后可以自动处理当前页面。
- 页面切换时创建独立上下文，返回时恢复原页面上下文。
- 正文和图片仅临时保存。
- 是否保留对话由用户控制。
- 用户自行提供 API Key。
- MVP 只接入一个模型，不提供多模型选择。
- 暂不建设账号、计费和业务服务端。
- “保留对话记录”默认关闭。
- 已启用页面刷新后自动重新解析，并保留该页面对话。
- URL 身份忽略锚点和常见跟踪参数，保留其他查询参数。
- 用户保留的对话一直保存到主动删除。
