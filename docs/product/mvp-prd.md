# 上下文阅读助手 MVP PRD

> 文档状态：需求基线 v1.0
> 产品形态：Chrome / Edge 桌面浏览器插件
> 目标用户：个人用户
> 覆盖内容：MVP PRD、页面交互流程、验收标准

## 1. 产品概述

### 1.1 问题背景

用户阅读外部技术博客时，经常会遇到不理解的专业术语、代码片段、架构图或流程图。当前通常需要复制文字或截图，切换到其他大模型产品，再粘贴内容并重新描述问题。

这一过程存在三个核心问题：

1. 操作链路长，打断连续阅读。
2. 外部模型缺少文章全文和当前阅读位置，容易脱离原文语境。
3. 图片需要额外截图和上传，架构图与前后文之间的关系容易丢失。

### 1.2 产品定义

上下文阅读助手是一款与当前网页绑定的浏览器插件。普通网页默认保持休眠；只有用户点击浏览器工具栏图标后，插件才在本地理解当前页面的正文结构和代码块，并显示页面内悬浮助手。用户可以随时停止当前页面的理解过程，也可以针对选中文字或文章全文就地提问。

### 1.3 核心价值

让用户在不离开当前阅读页面的情况下完成“发现疑问、提问、理解、回到原文继续阅读”的闭环。

### 1.4 MVP 成功定义

本产品仅供个人使用，MVP 暂不设置业务增长指标。满足以下结果即可视为产品能力成立：

- 用户无需复制文章全文或切换应用即可提问。
- 文本和全文问题都能结合当前文章语境回答。
- 默认悬浮球不改变网页布局，不持续占据正文阅读面积。
- 页面切换后，各页面上下文彼此隔离且可以恢复。

## 2. 用户与场景

### 2.1 目标用户

需要频繁阅读外部技术博客、开发文档和工程实践文章的个人用户。

### 2.2 核心场景

#### 场景 A：术语解释

用户选中不理解的专业名词，直接询问“它在本文中具体是什么意思”，回答同时说明通用定义和本文语境。

#### 场景 B：段落解释

用户选中一段复杂表述，要求简化解释、举例或说明它与前文结论的关系。

#### 场景 C：低干扰选词提问

用户划选一个术语或段落，选择区域上方出现“提问”按钮。点击后，悬浮球展开为对话卡片，并自动关联所选内容。

#### 场景 D：全文提问

用户未选中具体内容，直接询问文章的核心观点、方案取舍或某个概念在全文中的作用。

#### 场景 E：多页面切换

用户暂时切换到其他页面查看资料。新页面拥有独立上下文；返回原页面时，原有解析结果和对话恢复。

#### 场景 F：图片与区域解释

用户可以点选或双击页面中的图片，也可以自由框选当前可见页面区域。引用内容在对话框中预览，发送问题时自动使用视觉模型。

## 3. 产品原则

1. **原文优先**：回答首先服从当前文章内容，不能用通用知识覆盖或曲解原文。
2. **语境一致**：回答应优先依据当前文章；文章信息不足时，再使用模型通用知识补充。
3. **上下文可见**：用户能看到当前页面是否已经完成解析，以及本次问题关联了什么内容。
4. **少打扰**：未启用页面不显示控件、不读取内容；启用后只保留靠边悬浮球，不改变页面布局。
5. **会话隔离**：不同页面的正文和问答不能相互污染。
6. **用户可控**：页面理解只能由用户显式启动；用户可停止理解、清除临时上下文并决定是否保留对话记录。
7. **如实失败**：页面无法完整读取时必须明确提示，不能假装已经理解。

## 4. MVP 范围

### 4.1 P0 能力

- Chrome / Edge 桌面端浏览器插件。
- 工具栏点击后显示悬浮助手并在本地理解页面。
- 显式启用后提取常规技术博客的标题、URL、正文、标题层级、段落、列表和代码块。
- 展示页面解析状态。
- 支持选中文字提问。
- 支持点选、双击引用页面图片，以及自由框选当前可见页面区域提问。
- 支持不选中内容、直接针对全文提问。
- 支持悬浮球、紧凑输入卡片和自适应回答卡片之间渐进展开。
- 支持拖动悬浮球和缩放对话卡片，并在浏览器缩放后保持入口可见。
- 回答结合文章上下文和模型自身的通用知识。
- 支持当前页面内连续追问。
- 支持多个页面上下文的自动创建、隔离、切换和恢复。
- 正文和临时上下文在当前标签页会话内保存。
- 用户可选择是否在本地保留对话记录。
- 用户分别配置 DeepSeek 和 Doubao 所需的 API Key。
- 纯文本请求默认使用 DeepSeek，含图片请求自动使用 Doubao。

### 4.2 非目标

MVP 不包含：

- 用户手动选择模型、自动降级或效果比较。
- 产品账号、云端同步、计费和自建业务服务端。
- 联网搜索；“外部知识”仅指所接入模型自身具备的通用知识。
- PDF、视频、音频和移动端网页的专项支持。
- 多页面内容合并为一个知识库。
- 跨文章联合问答。
- 长期个人知识库、笔记管理、分享和团队协作。
- 自动启用网站列表。
- 登录受限网站和特殊站点的专项适配。
- 无限滚动、Canvas、iframe 或强交互页面的完整解析保证。
- 运营后台和业务指标体系。

## 5. 产品界面

### 5.1 插件入口

插件包含两个低干扰入口：

- **浏览器工具栏图标**：唯一的页面理解启动入口。点击后解析当前页面并打开网页内悬浮对话卡片。
- **网页悬浮球**：页面启用后的低干扰入口，显示当前状态，点击后恢复对话卡片。

### 5.2 悬浮对话卡片

对话卡片覆盖在网页上方，不改变网页宽度，至少包含：

- 当前页面解析状态。
- 当前问题关联内容的简要提示。
- 对话消息列表。
- 问题输入框与发送按钮。
- 设置和收起操作。
- “停止理解当前页面”操作。
- 可拖动的窗口缩放角点。
- 回答内容自适应增长，超过视口限制后仅在卡片内部滚动。

### 5.3 文字快捷入口

用户选中文字后显示轻量“提问”入口。点击后展开悬浮对话卡片，并将选中文字作为本次问题的焦点内容。

快捷入口不应遮挡选中文字或影响网页原有复制操作。

### 5.4 收起与恢复

- 用户点击关闭按钮或按 `Escape` 后，对话卡片收起为悬浮球。
- 收起只改变显示状态，不清除当前页面的解析结果和对话。
- 返回已经解析的页面时，恢复对应页面上下文，但仍默认保持悬浮球状态。

### 5.5 设置页

MVP 设置项包括：

- API Key。
- 是否保留对话记录。
- 清除全部本地对话记录。

模型标识和 API 地址属于实现侧预留配置，不作为用户设置项。MVP 不展示模型选择器。

设置页分别保存 DeepSeek 与 Doubao API Key；密钥用途和自动路由规则必须明确展示。

## 6. 功能需求

### FR-01 手动启用与停用

- 普通 HTTP/HTTPS 页面加载完成后保持休眠，不显示悬浮球、不提取正文、不显示选词提问入口。
- 用户点击工具栏图标后，插件才在浏览器本地解析当前页面并打开悬浮卡片。
- 页面理解不得自动调用模型 API；只有用户发送问题后，相关上下文才可发送到模型。
- 用户可以显式“停止理解当前页面”，清除该页面临时上下文并隐藏助手。
- 工具栏图标不得打开或占用浏览器侧边栏。

### FR-02 页面解析

插件应尽可能提取：

- 页面标题与规范化 URL。
- 文章标题、作者、发布时间（页面可识别时）。
- 标题层级与章节关系。
- 正文段落、列表和引用。
- 代码块及其语言标记（可识别时）。

系统应展示以下状态：

- 尚未配置 API Key。
- 正在解析。
- 上下文已就绪。
- 部分内容无法读取。
- 解析失败。

“上下文已就绪”表示系统已经具备在用户提问时检索和使用当前文章内容的能力，不代表每次都将全文原样发送给模型。

“部分内容无法读取”必须提供按需打开的诊断入口。正常对话页只显示轻量入口；诊断概览展示可读字符、正文入口、内容块数量和可能原因；用户可以继续进入单项详情查看检测依据和处理建议，也可以返回对话或重新理解页面。

### FR-03 文本提问

- 用户可以选中术语、句子或段落发起提问。
- 系统应将选中文字、所属章节、前后文及全文相关内容组合为问题上下文。
- 用户可以编辑或取消系统自动关联的选中文字。

### FR-03A 图片与区域提问

- 用户可以通过悬浮对话框进入图片点选或区域框选状态。
- 页面已启用时，双击已有图片可直接将其引用到对话框；不得阻止网页原有双击监听器。
- 点选图片和区域框选都基于当前可见页面截图，避免依赖图片跨域权限或登录态 URL。
- 引用图片后必须展示预览、模型路由提示和移除入口。
- 只有用户发送问题后，图片数据才发送至 Doubao。

### FR-04 悬浮球交互

- 悬浮球只在页面已经显式启用后显示，不改变正文布局。
- 用户可以拖动悬浮球，释放后吸附到最近页面边缘。
- 浏览器缩放、可视区域滚动或窗口尺寸变化后，悬浮球必须自动回到可见范围。
- 悬浮球显示解析中、就绪或失败状态，但不得自动展开对话。
- 点击悬浮球后原位展开为悬浮对话卡片。
- 收起后恢复为悬浮球，并保留当前页面上下文。
- 展开后的对话卡片可以通过标题区拖动位置。
- 对话卡片提供持续可见、可拖动且支持键盘操作的缩放角点，调整的是整个弹窗尺寸。
- 移动或缩放后的对话卡片不能超出当前可视区域。

### FR-05 选词快捷提问

- 只有当前页面已经启用时，用户选中术语、句子或段落后才显示“提问”按钮。
- 点击“提问”后自动关联选中文字、所属章节和前后文，并展开悬浮对话卡片。
- 快捷按钮不得影响网页原有复制和选择操作。

### FR-06 全文提问

- 用户无需选中内容即可对当前文章提问。
- 系统应从全文中选择与问题相关的章节和片段。
- 如果当前页面解析未完成，应阻止发送并说明原因。

### FR-07 回答规范

回答应包含或明确表达：

- 对用户问题的直接回答。
- 该概念或内容在本文中的具体含义。
- 必要时补充的模型通用知识。

回答不展示原文出处、段落编号、引用卡片或点击定位入口。文章未提供足够信息或模型无法确定时，应直接说明信息不足，不能把通用知识表述为文章结论。

### FR-08 连续追问

- 同一页面内的后续问题可以引用此前问答。
- 用户明确指代“刚才的概念”时，系统应保留必要的对话上下文。
- 对话过长需要裁剪时，应优先保留当前问题、最近对话、已选内容和相关原文，不得静默混入其他页面内容。

### FR-09 多页面上下文

上下文按“标签页 + 页面”隔离管理：

- 切换到另一个标签页时，当前上下文进入暂停状态，不被删除。
- 同一标签页跳转到新 URL 时，为新页面创建独立上下文。
- 通过前进、后退或再次访问返回原页面时，恢复该标签页内已有的页面上下文。
- 返回已解析页面时，恢复解析结果和对话。
- 新页面自动创建独立的未启用上下文，只有用户点击工具栏图标后才开始解析。
- 关闭标签页时，清除该标签页下的正文和临时页面上下文。
- 关闭浏览器会话时，清除所有未明确保留的临时页面上下文。

MVP 的建议上下文标识为 `tabId + 规范化 URL`。URL 规范化规则和刷新后的内容更新策略需在技术设计中确认。

### FR-10 对话记录

- 默认是否保留对话记录需在实现前确定，用户始终可以在设置中修改。
- 关闭“保留对话记录”时，关闭标签页即清除该标签页中的对话。
- 开启后，仅在浏览器本地保存问答文本。
- 已保留的对话记录与临时正文数据分开存储。
- 保留对话记录不代表长期保存文章全文。
- 用户可以删除单个页面的对话或清除全部对话。

### FR-11 模型 API

- 纯文本请求默认使用 DeepSeek Chat Completions API。
- 请求内容包含图片时自动使用 Doubao Ark Responses API。
- 用户分别提供两个模型的 API Key，产品不提供手动模型选择器。
- API 地址和模型标识由产品实现固定。
- 请求失败时允许用户重试，但不得在失败后静默切换模型。

### FR-12 隐私与安全

- 页面加载后不得自动解析正文；用户点击工具栏图标后才可在浏览器本地解析。
- 用户发送问题后，插件才按最终模型方案发送必要的文章上下文。
- UI 应明确告知当前页面内容可能发送至用户配置的模型 API。
- API Key 仅保存在浏览器本地，不进入网页 DOM、页面脚本、对话记录或普通日志。
- 正文不得进入长期存储，除非未来另有明确需求并由用户主动确认。
- 清除操作完成后，相关本地数据应不可再从产品界面恢复。

### FR-13 错误处理

至少覆盖：

- 页面无可识别正文。
- 页面仅解析出部分内容。
- API Key 缺失或无效。
- API 限流、超时、网络错误和服务不可用。

错误提示必须说明失败对象和可执行的下一步，例如重新解析、检查 API Key 或重试请求。

## 7. 页面交互流程

### 7.1 首次配置

```text
安装插件
  -> 打开设置页
  -> 输入 API Key
  -> 插件验证 API Key 必要字段
  -> 配置完成
```

如果模型 API 尚未最终确定，开发态可使用实现侧占位配置，但正式可用版本必须提供明确配置说明。

### 7.2 页面加载与手动启用

```text
用户打开技术博客
  -> 插件保持休眠，不读取正文
  -> 用户点击浏览器工具栏图标
  -> 网页内对话卡片显示“正在理解页面内容”
  -> 插件在浏览器本地解析正文与结构
  -> 状态变为“页面内容已理解”“部分内容已理解”或明确失败
```

### 7.3 选中文字提问

```text
用户选中文字
  -> 选择区域上方出现“提问”入口
  -> 用户点击入口
  -> 悬浮球展开为对话卡片
  -> 卡片展示已关联的文字
  -> 用户输入问题
  -> 系统检索全文相关内容
  -> 模型回答在同一卡片内展开
```

### 7.4 悬浮卡片收起

```text
用户完成阅读辅助
  -> 点击卡片关闭按钮或按 Escape
  -> 对话卡片收起
  -> 页面边缘恢复悬浮球
  -> 解析结果和对话仍保留在当前标签页会话
```

### 7.5 工具栏入口

```text
用户点击浏览器工具栏中的插件图标
  -> 浏览器不打开侧边栏
  -> 当前网页内的悬浮对话卡片展开
  -> 当前页面开始或重新开始理解
```

### 7.6 页面切换与恢复

```text
页面 A 已解析并存在对话
  -> 用户切换至页面 B
  -> 页面 A 上下文暂停
  -> 页面 B 保持休眠，不沿用页面 A 内容
  -> 用户点击工具栏后，页面 B 创建独立上下文并开始解析
  -> 用户返回页面 A
  -> 自动恢复页面 A 的解析结果和对话
```

### 7.7 显式停止

```text
用户点击“停止理解当前页面”
  -> 清除当前 URL 的正文、选择内容和临时对话
  -> 隐藏悬浮助手和选词入口
  -> 再次点击浏览器工具栏图标后才能重新理解
```

### 7.8 关闭与清理

```text
用户关闭标签页
  -> 清除该标签页下的正文和临时上下文
  -> 若未开启对话保留，同时清除对话
  -> 若已开启对话保留，仅保留问答文本
```

## 8. 状态模型

单个页面上下文至少具有以下状态：

```text
UNACTIVATED
  -> 用户点击工具栏图标
  -> PARSING

PARSING
  -> READY
  -> PARTIAL
  -> FAILED

READY / PARTIAL
  -> ASKING
  -> ANSWERING
  -> READY / PARTIAL

任意活动状态
  -> 用户停止理解
  -> UNACTIVATED

任意活动状态
  -> SUSPENDED
  -> 恢复到离开前状态

标签页关闭
  -> DISPOSED
```

约束：

- `PARSING` 只在浏览器本地处理页面，不得自动调用模型 API。
- `FAILED` 状态允许重新解析。
- `PARTIAL` 状态允许提问，但每次回答都应携带上下文不完整提示。
- `SUSPENDED` 只表示页面暂时不可见，不代表数据被清除。
- `DISPOSED` 后临时上下文不可恢复。

## 9. 验收标准

### AC-01 新页面默认休眠

**Given** 用户首次打开一个普通技术博客页面
**When** 页面加载完成
**Then** 插件不显示悬浮球、不提取正文、不显示选词提问入口，也不调用模型 API。

### AC-02 工具栏点击后显式解析

**Given** 当前页面包含可识别正文
**When** 用户点击浏览器工具栏图标
**Then** 网页内卡片先显示“正在理解页面内容”，随后在本地解析正文结构和代码块，并最终显示就绪、部分可用或失败状态；解析过程不调用模型 API。

### AC-03 选中文字提问包含局部与全文上下文

**Given** 当前页面已就绪
**When** 用户选中一个术语并发起提问
**Then** 请求上下文至少包含选中文字、所属章节、邻近段落和全文相关片段，回答说明该术语在本文中的含义。

### AC-04 普通段落可以解释

**Given** 用户选中一个复杂段落
**When** 用户要求“用更简单的话解释”
**Then** 回答围绕所选段落展开，不回答无关章节。

### AC-05 悬浮球展开为对话卡片

**Given** 页面悬浮球已显示
**When** 用户点击悬浮球
**Then** 原位展开紧凑对话卡片并聚焦问题输入框，不打开浏览器侧边栏。

对话卡片必须支持鼠标拖动缩放和键盘方向键缩放；浏览器缩放或窗口尺寸变化后，悬浮球与卡片入口不得停留在可视区域外。

### AC-06 选词入口自动引用

**Given** 用户在文章中选中术语或段落
**When** 用户点击选择区域上方的“提问”按钮
**Then** 对话卡片展开并展示已引用的选中文字。

### AC-07 对话卡片可无干扰收起

**Given** 对话卡片已展开
**When** 用户点击关闭按钮或按 Escape
**Then** 卡片收起为悬浮球，页面上下文和对话不被清除。

### AC-08 支持全文提问

**Given** 页面上下文已就绪且用户未选择任何内容
**When** 用户询问文章整体观点
**Then** 系统从全文选择相关章节回答；文章没有提供足够信息时必须说明。

### AC-09 回答不展示原文出处

**Given** 模型基于文章内容完成回答
**When** 回答展示完成
**Then** 页面不展示原文出处、段落编号、引用卡片或点击定位入口。

### AC-10 连续追问保持当前页面语境

**Given** 用户刚针对一个概念获得回答
**When** 用户追问“这里为什么不用另一种方案”
**Then** 系统能够关联上一轮问题和回答，不要求用户重新选择文字。

### AC-11 页面上下文相互隔离

**Given** 页面 A 和页面 B 均已由用户显式启用并解析
**When** 用户在页面 B 提问
**Then** 请求不得包含页面 A 的正文或对话，除非未来新增且由用户主动触发跨页面能力。

### AC-12 返回原页面时恢复

**Given** 页面 A 已解析并存在对话，用户随后切换到页面 B
**When** 用户返回页面 A
**Then** 插件恢复页面 A 的解析状态、已选内容和对话，默认仅显示悬浮球。

### AC-13 新页面独立且保持休眠

**Given** 用户已在页面 A 使用插件
**When** 用户跳转到从未访问的页面 B
**Then** 页面 B 创建独立的未启用上下文，不得自动解析正文，也不得沿用页面 A 的正文或对话。

### AC-14 关闭标签页清除临时内容

**Given** 一个标签页中存在多个页面的解析结果
**When** 用户关闭该标签页
**Then** 该标签页下的正文和临时页面上下文全部清除。

### AC-15 对话保留开关生效

**Given** 用户关闭“保留对话记录”
**When** 用户关闭对应标签页
**Then** 对话与临时上下文一并清除。

**Given** 用户开启“保留对话记录”
**When** 用户关闭对应标签页
**Then** 本地仅保留问答文本，不保留文章全文。

### AC-16 单模型配置

**Given** 用户打开设置页
**When** 查看模型相关设置
**Then** 页面只展示单一模型所需的 API Key，不出现 API 地址、模型标识、模型列表、模型切换或自动降级选项。

### AC-17 API Key 缺失时阻止请求

**Given** 用户未配置 API Key
**When** 用户尝试发送问题
**Then** 插件阻止请求，提示配置 API Key，并提供进入设置页的入口。

### AC-18 API 失败时可重试但不切换模型

**Given** 模型 API 返回超时、限流或服务不可用
**When** 本次回答失败
**Then** 插件保留用户问题并提供重试，不自动调用其他模型。

### AC-19 部分解析不得伪装完整

**Given** 插件只读取到部分文章
**When** 用户基于当前页面提问
**Then** UI 和回答均提示上下文不完整，并避免声称已经理解全文。

### AC-20 清除操作不可从产品界面恢复

**Given** 用户主动清除当前页面上下文或全部本地对话
**When** 清除完成
**Then** 对应内容不再出现在悬浮对话卡片、历史记录或页面恢复流程中。

## 10. MVP 发布门槛

只有同时满足以下条件才可视为 MVP 完成：

- AC-01 至 AC-20 全部通过。
- 至少在 10 篇结构不同的公开技术博客上完成手工验证。
- 至少覆盖纯文本文章、包含代码块的文章、包含架构图的文章三类页面。
- 未发现不同页面上下文串用问题。
- 未发现 API Key 出现在网页 DOM、普通日志或导出的对话记录中。
- 页面关闭后的临时正文均按要求清除。

## 11. 已确认决策

- 产品供个人使用。
- 主要阅读对象是外部技术博客网页。
- 图片理解暂不纳入当前版本。
- 允许使用模型自身的外部通用知识。
- 新页面默认休眠；只有用户点击工具栏图标才在本地解析并显示悬浮助手。
- 选词入口只在当前页面已启用时出现；工具栏图标和选词入口均不打开侧边栏。
- 页面切换时创建独立上下文，返回时恢复原页面上下文。
- 正文仅临时保存。
- 是否保留对话由用户控制。
- 用户自行提供 API Key。
- MVP 只接入一个模型，不提供多模型选择。
- 暂不建设账号、计费和业务服务端。
- “保留对话记录”默认关闭。
- 已解析页面刷新后恢复既有会话，但不自动重新解析；再次点击工具栏图标才刷新理解结果。
- URL 身份忽略锚点和常见跟踪参数，保留其他查询参数。
- 用户保留的对话一直保存到主动删除。

## 12. 待确认项

以下事项不阻塞产品原型，但会阻塞最终技术实现：

1. 具体模型、API 协议、接口地址、模型标识和请求限制。
2. 模型 API 是否支持流式输出，以及 MVP 是否启用流式回答。

4. 按 AC-01 至 AC-20 建立功能测试清单。
