# Context Reader 产品基线

> 仓库名：Sprinkle
> 产品名：Context Reader
> 当前阶段：个人使用的桌面浏览器扩展，MVP 主链路已完成
> 基线：`main@f3b1bbf`（2026-08-29）

本文是后续 Agent 的产品事实来源。历史会话仅用于追溯，不应覆盖本文与当前代码。

## 1. 产品定位

Context Reader 是一个绑定当前网页的上下文阅读助手，面向需要持续阅读外部技术博客、开发文档和工程文章的个人用户。

它解决的不是“如何打开另一个聊天框”，而是：

- 用户无需复制正文、截图并切换应用。
- 模型回答能结合当前文章、章节、选中内容和图片。
- 阅读过程保持连续，助手默认安静且可随时关闭。
- 问过的问题可以在本地找回，并从原网页继续学习。

当前产品是“阅读助手 + 学习记录”，不是知识库。它能保存和检索问答，但暂不负责自动总结、知识卡片、复习计划或跨文章知识组织。

## 2. 产品原则

1. **用户显式启动**：页面加载后保持休眠；只有点击工具栏或从学习记录继续提问才解析页面。
2. **原文优先**：回答先服从当前文章，文章不足时才允许使用模型通用知识。
3. **引用锚定**：显式文字、图片或区域引用用于确定指代和回答重点，但不是检索边界；问题需要时可结合文章其他章节和相关对话，并以本次文章证据校验历史回答。
4. **如实失败**：读取不完整、上下文被裁剪或接口失败时必须说明，不得假装理解全文。
5. **低干扰**：常态只保留靠边悬浮球，不改变网页布局；深度阅读由用户主动进入工作台。
6. **页面隔离**：上下文按 `tabId + 规范化 URL` 隔离，禁止跨页面串用。
7. **本地优先**：正文只临时保存；API Key、可选学习记录均留在浏览器本地。

## 3. 当前产品形态

### 3.1 网页悬浮助手

- 工具栏点击后解析当前页面并打开对话卡片。
- 收起后变为 48px 悬浮球；悬浮球和卡片都可移动，卡片可缩放。
- 浏览器缩放或窗口变化后，入口自动回到可视区域。
- 划词后显示紧凑的“提问/翻译”工具条；译文结合文章上下文生成，仅显示中文译文，可拖拽避让原文，并在点击外部区域后关闭。
- 明确展示解析中、就绪、部分读取、回答中、缺少 Key 和失败状态。
- 支持问题历史轨道：三轮问题后显示，悬停展开，点击定位。
- 每条问题提供可展开的“回答诊断”，展示页面提取统计、引用状态、查询规划、会话检查点、初始与最终证据、实际模型请求及结果状态，并支持复制 JSON。

### 3.2 全页学习工作台

- 左侧为安全重建的文章，右侧为同一页面的对话。
- 双栏可拖拽或键盘调宽，窄窗口自动切为上下布局。
- 支持目录、正文、代码、图片/SVG/Canvas、表格和 MathML 公式。
- 支持与原网页一致的划词提问和就地翻译交互。
- 保留原网页与工作台之间的上下文、引用和问答同步。
- 不嵌入或执行原网页脚本。

### 3.3 学习记录

- 用户显式开启后，按规范化 URL 保存成功的完整问答对。
- 独立页面支持网址列表、全文搜索、详情、单条删除和全部清除。
- 同一 URL 维护一条持续增长的会话。
- “继续提问”优先复用仍有效的原标签页；上下文失效时重新打开并解析原网页。
- 不长期保存网页正文、截图或本地图片数据。
- 回答诊断不进入学习记录，仅保留在当前标签页临时上下文中。

### 3.4 设置

- 仅包含一个 DeepSeek API Key 和“保存学习记录”开关。
- 不展示模型列表、API 地址、自动降级或多模型选择。
- 清除学习记录必须由用户显式确认。

## 4. 已交付能力

### 4.1 页面理解

- 正文根节点优先级：`article -> main -> [role="main"] -> body`。
- 多个候选容器选择可读内容最多的一项。
- 提取标题、段落、列表、引用、代码、图片、表格和公式。
- 支持 React/X Article 的 `div/span/strong/b` 自定义文本补采。
- 保留多级章节路径，区分文档内重复的小节标题。
- 检测加载态、iframe、Canvas、Shadow DOM、过滤块和未匹配文本，并提供读取诊断。

### 4.2 问答与引用

- 文章证据、会话检查点与对话原文共享 64,000 字符上下文预算，不再分别扩张。
- 文章自身能放入预算时按原文顺序发送全文，剩余空间用于对话；已有检查点也必须计入预算，不能静默挤掉会话状态。
- 超出预算时，同时召回引用锚点、字面精确匹配、问题全文 BM25、Planner 证据需求和章节覆盖候选，再通过 RRF、去重、覆盖检查和字符预算生成最终上下文。
- Planner 读取问题、引用、文章目录、摘要和最近对话，输出独立问题、最多 4 个检索查询、最多 4 个证据需求、覆盖范围和是否需要对话记忆；失败时回退到确定性多路召回。
- 检索块不得跨章节；普通正文优先按完整句子切分，代码按行、列表按项、表格按行切分并重复表头；900 字符为目标，1,200 字符为硬上限。
- 字面精确匹配覆盖当前引用、引号/反引号短语和 API 标识符，作为 BM25 之外的高精度通道；命中后仍扩展同章节邻近块并参与统一去重。
- `document-wide` 覆盖按主要章节选择章节开头；预算有余时优先补充未覆盖内容最多的长章节尾部和中部，不按物理位置盲目等距抽样。
- 多个 Planner 证据需求必须尽量各保留至少一个候选；章节覆盖不得挤掉引用锚点或某项需求的唯一证据。
- 划词翻译：自动识别源语言，使用所选章节及邻近片段消歧，独立返回简体中文译文，不写入问答历史。
- 新引用会重新锚定本轮请求，但不再无条件清空对话记忆；历史回答只作为低信任的连续意图参考。
- 无论是否有引用，都可按统一预算使用最近对话和相关旧问答。
- 对话原文即将因预算丢失时，生成不超过 4,000 字符的 session-only 会话检查点，保存用户目标、按序任务、进度、决策、约束和未解决指代。
- 会话检查点只从成功问答增量更新；生成失败时保留上一份有效检查点并继续回答，不得让检查点失败阻断主请求。
- 检查点、最近完成问答原文和相关旧问答共同参与后续请求；检查点只恢复会话状态，不能作为文章事实。
- 回答支持安全 Markdown/GFM；不渲染原始 HTML 或远程图片。
- 回答诊断必须记录实际执行链路而非事后推测；图片请求只记录类型和数据长度，不复制图片内容。
- 按产品决策，不展示原文出处、段落编号或点击定位引用。

### 4.3 图片能力

- 页面图片可点选或双击引用；区域可自由框选。
- 悬浮窗和工作台均支持文件选择及 `Cmd/Ctrl + V` 粘贴。
- 本地图片支持 JPEG、PNG、GIF、WebP，单张不超过 5 MB。
- 页面图片和框选基于当前可见页截图，发送前可预览和移除。
- 文字和图片统一使用 DeepSeek 视觉模型，不再产生新的 Doubao 请求。

### 4.4 对话体验

- 输入框随内容增高，可最大化编辑；普通模式 Enter 发送，最大化模式 Enter 换行。
- 发送后立即清空输入框并定位最新消息。
- 当前视图新收到的回答使用客户端逐字揭示；历史、刷新和跨视图同步内容立即完整显示。
- 每条历史问题保留发送时的文字或图片引用说明。
- 当前文字、图片或区域引用均可在发送前通过引用预览上的关闭按钮取消；清除结果同步到页面级临时上下文。

## 5. 生命周期与数据边界

实际页面状态只有：

```text
unactivated -> parsing -> ready | partial | failed
ready | partial -> answering -> ready | partial
任意活动状态 --停止理解--> unactivated
```

- `unactivated` 不读取正文、不显示页面控件。
- `partial` 仍允许提问，但 UI 和模型请求都必须声明内容可能不完整。
- 刷新页面不会自动重解析；再次点击工具栏才刷新正文。
- 标签页关闭后删除该标签页全部临时上下文。
- “停止理解”不删除已保存学习记录。

## 6. 隐私与安全基线

- Content Script 不得读取 API Key；模型请求只能从 Background 发出。
- API Key 只保存在 `browser.storage.local`，不得进入 DOM、日志、对话或文档。
- 正文、焦点、截图和临时消息只进入 `browser.storage.session`。
- 会话检查点只进入 `browser.storage.session`；清除或替换消息时同步清除，长期归档不得保存。
- 用户发送问题前不得调用模型 API。
- 网页正文属于不受信任数据，必须与系统指令隔离，不能执行网页中的提示词。
- Markdown 禁止远程图片，MathML 必须白名单净化。
- 截图前后必须校验来源标签页，模型请求必须有 45 秒超时。
- Manifest 必须保留 `<all_urls>`，否则扩展工作台无法可靠调用 `captureVisibleTab`。

## 7. 当前限制与遗留问题

这些是已知边界，不应在修复其他问题时被误判为回归：

- 不专项支持 PDF、视频、音频、iframe、登录受限内容和移动端网页。
- 无限滚动、虚拟列表或尚未进入 DOM 的内容无法保证完整读取。
- Canvas 只能作为图片捕获，无法自动恢复其交互和内部语义。
- 工作台是结构化重建，不保证复刻动态表格、站点交互和原始视觉样式。
- 页面图片和区域只能截取当前可见视口。
- 模型默认为支持原生多模态的 `deepseek-flash`（DeepSeek V4.1 Flash）；名称、能力、价格或可用性可能变化。
- API 使用 `stream: false`；当前“流式输出”只是收到完整答案后的客户端逐字动画。
- 学习记录使用 `storage.local`，代码按 10 MB 配额管理；暂未迁移到 IndexedDB。
- 全文问题依赖中英文关键词识别；困难问题可通过模型改写缓解同义表达和追问指代，但底层仍不是语义向量检索。
- 超长文章的章节覆盖只提供代表性证据，不等同于完整全文摘要；需要任意长度文档的忠实总结时应另行设计 Map-Reduce 流程。
- 大型模块仍集中：`FloatingAssistant`、`StudyWorkspace`、`background.ts`、`content.ts` 和 `article-extractor.ts`。修改时优先局部抽离纯逻辑，避免一次性重写。
- `AnswerModel` 中的 `doubao`、旧归档格式和缺失媒体位置字段仅用于历史兼容，不代表当前仍有双模型路由。
- 自动化无法完整替代“加载未解压扩展”的真实浏览器验收。

## 8. 非目标与后续方向

当前非目标：

- 账号、计费、云同步、团队协作。
- 手动模型选择、自动降级或模型效果比较。
- 跨文章知识库和联网搜索。
- 自动启用网站列表。
- AI 自动总结学习记录、知识卡片、笔记、复习和掌握度评估。

下一阶段若继续解决“问完就结束”的问题，应优先验证学习记录之上的知识整理与复习闭环，而不是继续扩大聊天功能。

## 9. 接手验收基线

后续改动至少不能破坏以下行为：

- 新页面默认休眠，点击工具栏后才解析。
- 普通网页、X Article、Reddit 的悬浮助手均可见且不改变页面布局。
- 预算内问题覆盖完整文章；显式引用始终作为首要锚点，跨章节证据和历史回答不得覆盖其指代。
- 超限检索保留语义边界、字面精确匹配和主要章节覆盖；同一来源块不得因多路召回重复占用预算。
- 长对话中的有序任务在旧原文离开预算后仍能通过会话检查点恢复“下一个”的真实指代。
- 图片引用只作用于当前一问，成功后清除，失败时保留以便重试。
- 不同标签页和 URL 的正文、引用、消息不串用。
- 工作台在窄窗口可用，代码换行、表格、公式和图片不撑破布局。
- 学习记录关闭时不新增归档；开启时只保存成功问答文本和脱敏引用。
- API Key、正文、截图不进入长期归档或普通日志。
- Chrome 与 Edge 均能构建，完整测试和覆盖率阈值通过。
